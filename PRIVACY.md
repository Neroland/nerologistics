# NeroLogistics privacy & telemetry disclosure

NeroLogistics includes anonymous error reporting so that crashes and bugs caused by the mod can be
found and fixed. It is **on by default** and **opt-out** (see [How to opt out](#how-to-opt-out)).
This page is the full disclosure required by CurseForge's moderation
rules for mods that use an external analytics/error service, and it documents how the mod is
designed to comply with the GDPR (EU) and POPIA (South Africa).

> **Status:** NeroLogistics' own Sentry DSN is built into published jars, so reporting is live unless
> you opt out. A build with the DSN blanked (`NeroLogisticsTelemetry.DSN`) sends **nothing**,
> regardless of the settings below.

## What is collected (error reporting)

When an error **caused by NeroLogistics code** occurs, a report is sent to
[Sentry](https://sentry.io) (hosted in the **EU** — `ingest.de.sentry.io`) containing:

- the stack trace of the error and the error message (file paths containing your operating-system
  account name are masked before sending),
- the NeroLogistics version, the loader (NeoForge / Forge / Fabric), and whether the game is a
  client or dedicated server,
- the operating system name/version and Java version,
- one of the mod's own configuration flags (whether per-player throughput attribution is enabled),
  so a crash that only happens at non-default settings can be reproduced,
- a random event ID generated by Sentry for the individual report.

Reports are de-duplicated and hard-capped at 10 events per game session.

## What is NOT collected

- **No IP address** is stored (`sendDefaultPii` is disabled; Sentry discards the sender IP).
- **No username, player UUID, or machine/host name** (`attachServerName` is disabled and the user
  and server-name fields are cleared before every report is sent).
- **No world data, chat, coordinates, inventories, network layouts, or gameplay analytics** of any
  kind — nothing about what you built or shipped leaves the game.
- **No advertising or tracking identifiers** — there is no persistent ID linking reports from the
  same player or machine.
- **No list of your other installed mods.**
- Errors caused by other mods or by Minecraft itself are filtered out and never sent.

## How to opt out

Crash reporting is **on by default**. To opt out, set the following in
`config/nerologistics.properties` (created on first launch):

```properties
telemetryEnabled=false
```

This is a client-local switch (not server-synced, so a server cannot turn your reporting back on)
and takes effect on next launch. Error reporting then sends nothing, and nothing is ever sent before
the config — and therefore your choice — has been loaded. Server owners can opt out for the whole
server the same way.

## Player data inside the mod (POPIA / GDPR)

NeroLogistics stores **no personal data by default** — networks, conduits, terminals, storage cells,
drive bays, ports, drones, shipments and dashboards are keyed by block position and dimension, never
by player. The only player-linked data is listed below; each item exists only while the feature that
needs it is in use, holds a UUID at most (never a name), and is erased through **Neroland Core's shared
data-erasure hook**.

### Per-player throughput attribution (opt-in, off by default)

A server may opt in to per-player attribution by setting the following in
`config/nerologistics.properties`:

```properties
# opt-in: attribute cargo-port shipments to the placing player (UUID only); off = no player data
perPlayerThroughputAttribution=false
# days to retain per-player attribution before auto-prune (0 = keep until erased)
attributionRetentionDays=30
```

Only when `perPlayerThroughputAttribution=true` does NeroLogistics store:

- the **UUID** of the player who placed a rocket cargo port (never their name), written to that
  block's NBT in the world save, and
- an in-memory per-UUID shipment total with a last-updated day stamp, used by the logistics
  dashboard and discarded when the server stops.

This data is **minimised** (UUIDs only), **retention-pruned** after `attributionRetentionDays`
(default **30** days; `0` keeps it until an explicit erase request), and registered with Core's
data-erasure hook — so a single erase request, or Core's inactivity sweep, purges a player's
NeroLogistics data alongside every other Neroland mod. Any player can also opt themselves out with
`/nerologistics privacy optout` (their record and loaded ports' owner UUID are dropped at once,
unloaded ports on next load). With the option off (the default, **`false`**), none of this is stored,
and turning it off also drops any owner already recorded on a cargo port.

### Rocket cargo port dispatcher (Nerospace routing only)

With Nerospace 1.3.0+ installed, a rocket
cargo port launches real Nerospace cargo flights, and Nerospace only launches *on behalf of a player*.
So a port stores one more UUID, the **dispatcher**: the player who last picked a Nerospace destination
on it.

- **Purpose and lawful basis:** needed to perform the shipping that player configured (performance of
  the requested function). It is separate from the analytics attribution above and is stored whatever
  `perPlayerThroughputAttribution` says.
- **Data minimisation:** the UUID only, never a name. It is never logged, never sent to telemetry, and
  shown to players only as "you", "someone else" or "nobody".
- **Retention:** the life of the port block. Breaking the port deletes it, and so does the next player
  who configures the port (they become the dispatcher).
- **Erasure:** Core's shared data-erasure hook clears it from every loaded port at once, and from
  unloaded ports via the same tombstone list the attribution owner uses, the next time those ports load.
  An erased dispatcher leaves the port listing public pads only and unable to launch until someone
  configures it again.

### Optional freight fee (NeroEconomy only)

If NeroEconomy is installed and the server sets `freightFee` above `0` (default `0` = off), the dispatcher's UUID is passed to NeroEconomy for that one
charge. NeroLogistics stores nothing new about the player for this: the request key is a world-wide
counter (`freight/<n>`), never a UUID or name, nothing is logged, and only the dispatcher is shown why a
charge was refused — other players see the generic "cannot pay" line. A port remembers only a yes/no
flag that its next launch is already paid. The charge itself is a row in NeroEconomy's ledger
(`nerologistics/freight_fee`), covered by NeroEconomy's own privacy notice, export and erasure.

### World data kept for the dashboard (no player data)

NeroLogistics also remembers which Nerospace flights it requested (flight, pad and port ids, dimensions,
positions and ticks — no player data) so its dashboard stays right across restarts, and, since 0.6.0, the
dashboard's per-dimension throughput totals themselves (keyed by dimension id only — no player data).

### Quest perks (NeroQuests or any quest pack, optional)

A quest reward may open one of two record gates NeroLogistics ships (`nerologistics:hook/dashboard_badge`, `nerologistics:hook/cell_preset`). When one opens,
NeroLogistics stores a small per-player entry in the world (`nerologistics:quest_perks`): the player's
**UUID** (never a name), two yes/no flags, and — once the player saves one — their own storage-cell preset
(nine ghost item ids and a priority).

- **Purpose and lawful basis:** delivering the cosmetic reward the player earned (a dashboard badge line
  only they see; Save/Load buttons for their preset). Neither perk gates access to anything.
- **Data minimisation:** nothing is logged or sent to telemetry, and nothing is shown to other players.
- **Retention:** the life of the world, or until erased.
- **Erasure:** Core's shared data-erasure hook removes the entry in full and refreshes the recovery backup
  at once.

The quest pack also reads one progression gate, `nerologistics:first_shipment`, opened for the player a
rocket cargo port's accepted launch is attributed to (dispatcher, opt-in owner, or the player who last picked
the destination — the last of those is held in memory only and never written to disk). Gate rows are stored
and erased by Neroland Core under its own privacy notice. The world-log threshold channels NeroLogistics
publishes carry a dimension id as their scope — never a player, UUID or coordinates.

### NeroLink companion module

When a NeroLink bridge is installed (and `enableLinkModule` is left on), NeroLogistics answers a
companion client's questions through Neroland Core's link API. It adds **no new stored data**:

- Every answer is scoped to the **requesting player's own surroundings** — their dimension, within 128
  blocks, while they are online — and never lists the whole server.
- Answers carry block positions, counts, item ids and settings only. **No player UUID or name** is
  ever included; a cargo port's owner or dispatcher is never read out (a port says only whether *the
  requester* is its opt-in owner).
- Broadcast events carry dimension ids and counts only — never a position or a person.
- On servers that opted into per-player attribution, a port's opt-in owner may receive a private
  "shipment departed" event and a "shipment queue full" alert. The owner UUID is used only to address
  them; the alert lives in Core's per-player alert store and is erased with everything else by Core's
  data-erasure hook. The dispatcher is never used by the link module.
- Nothing is logged with a player identity.

See the [wiki Companion Link Module page](wiki/Link-Module.md) for the details.

See the [wiki Dashboard & Privacy page](wiki/Dashboard-and-Privacy.md) for the in-game side.

## Legal basis and your rights (GDPR / POPIA)

Error reports are processed on the basis of **legitimate interest** (GDPR Art. 6(1)(f); POPIA
s11(1)(f)): keeping the mod functional and crash-free, using the minimum data necessary. They are
engineered to contain no directly identifying personal information, are stored in the EU, and are
retained only for Sentry's standard retention period before automatic deletion.

In-world data (attribution when a server has opted in, the dispatcher, quest perks) is held by that
server's operator and is erased through Core's data-erasure hook.

## Contact

To exercise any data-subject right (access, deletion, objection) for an error report, contact
**[info@neroland.co.za](mailto:info@neroland.co.za)** with the approximate date/time of the crash so
the matching event can be located and removed. Sentry acts as a data processor; see the
[Sentry privacy policy](https://sentry.io/privacy/) and
[data processing addendum](https://sentry.io/legal/dpa/).

## Changes to this policy

If a future version of NeroLogistics ever collects additional data, this page will be updated
**before** that version is released, the change will be called out in the changelog, and the same
opt-out (`telemetryEnabled=false`) will continue to cover everything error reporting sends.
